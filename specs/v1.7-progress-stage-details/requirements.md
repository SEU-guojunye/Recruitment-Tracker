# Recruitment Tracker v1.7 进度节点详情需求

## 问题与范围

当前招聘进度节点仅保存环节名称、阶段、终态和日期，无法记录面试会议链接、面试反馈、准备事项等节点上下文。本次在现有岗位投递明细和“编辑进度”流程内补充节点备注，并允许电脑扩展端与手机只读网页展开查看节点详情。

## 产品规则

- 每个 `progressStage` 新增可选字符串 `note`，上限与通用备注一致，为 5000 个字符。
- “面试备注”和“面试链接”共用一个多行文本字段；备注允许换行。
- 备注中的 HTTP/HTTPS URL 在节点详情中显示为可点击外链，其他文本按原文展示。
- 节点日期为空时详情显示“未填写”；节点备注为空时详情显示“暂无备注”。
- 每条投递同一时间最多展开一个节点；再次点击已展开节点时收起。
- 未到达节点仍允许展开，便于提前保存面试链接或准备事项。
- 旧本地数据、旧 CloudBase 快照和缺少 `note` 的 `progressStages` CSV 自动补 `note: ""`，不提升 `schemaVersion`。
- CSV 不新增独立列，节点备注继续包含在 `progressStages` JSON 中。
- 公司图标依次尝试 Favicon.im 和 FaviconKit 外部 API；全部来源失败时显示浅主题色圆角矩形和公司名称首字，不显示破损图片。

## 用户故事与验收标准

### R1. 节点备注数据契约

作为电脑端编辑者，我希望每个进度节点保存独立备注，以便面试信息不会混在投递总备注中。

- 当系统创建默认进度节点或新增节点时，系统应将 `note` 初始化为空字符串。
- 当旧数据中的节点缺少 `note` 时，兼容层应在校验前补为空字符串。
- 当保存或导入的节点备注不是字符串或超过 5000 个字符时，系统应在写入前拒绝整次操作。
- 当进度工作流被替换、切换、导出或同步时，系统应无损保留每个节点的 `note`。

### R2. 编辑进度中的备注填写

作为电脑端编辑者，我希望在每个进度环节中填写备注或链接，以便集中维护本轮面试信息。

- 当用户打开“编辑进度”时，每个环节应显示“备注或面试链接”多行输入框并回填已有内容。
- 当用户保存进度时，系统应保留备注中的换行并移除首尾空白。
- 当备注超出上限时，界面应阻止继续输入，并由核心校验再次兜底。
- 当新增环节时，新环节的备注应为空。

### R3. 节点详情展开

作为电脑端或手机端查看者，我希望点击任意进度节点查看日期和备注，以便快速理解该环节详情。

- 当用户点击进度节点时，时间线下方应展开该节点详情并显示环节名称、日期和备注。
- 当用户点击另一个节点时，系统应切换到新节点详情，而不是同时展开多个面板。
- 当用户再次点击当前节点时，系统应收起详情。
- 当节点备注包含 HTTP/HTTPS URL 时，系统应使用新窗口安全外链打开；非 URL 文本不得被解释为 HTML。
- 当用户使用键盘操作节点时，Enter 或 Space 应能切换详情，并通过 `aria-expanded` 和 `aria-controls` 表达状态。

### R4. 响应式与只读边界

作为手机端查看者，我希望节点详情适应窄屏且不产生横向滚动。

- 当视口宽度为 320、360、390 或 430px 时，详情面板应占满投递卡片宽度且页面不得产生水平滚动。
- 当 Web 端处于只读模式时，系统应允许展开节点详情，但不得显示备注编辑控件。
- 当电脑端在进度编辑器中预览时间线时，节点详情展开不得修改尚未保存的数据。

### R5. 公司图标失败回退

作为列表查看者，我希望公司图标加载失败时仍有清晰、稳定的公司识别标记。

- 当图标链接无效、网络请求失败或图片解析失败时，应显示公司名称首字；名称为空时显示“企”。
- 回退图标应使用 34px 方形区域、6px 圆角、浅主题色填充和 18px 主题色粗体首字。
- 当图标成功加载时，应移除回退背景并保持当前高清图片展示。
- 回退状态不得改变公司列尺寸、显示破损图片或重复朗读公司名称。

### R6. 公司图标多源解析

作为列表查看者，我希望系统从多个来源尝试企业图标，以提高图标命中率和清晰度。

- 当公司招聘链接合法时，应依次尝试 Favicon.im 高清 API 和 FaviconKit 128px API。
- 当前来源加载或图片解析失败时，应自动尝试下一来源，不阻塞公司列表。
- 任一来源加载成功后应停止切换；只有全部来源失败后才显示首字回退。
- 向第三方 API 只发送经校验和编码的 hostname，不发送招聘路径或查询参数。

### R7. 回归与交付

- 当实现完成时，核心模型、兼容层、CSV、快照、编辑器、共享 UI 和 E2E 测试应覆盖节点备注的创建、保存、兼容、展开和外链行为。
- 每个实施阶段完成后，应先通过相关检查再提交一次 Git。
- 本次不自动部署 CloudBase，也不直接改写线上快照数据。

## 非目标

- 不新增富文本编辑器、附件上传、提醒或日历集成。
- 不为备注内的非 HTTP/HTTPS 文本生成链接。
- 不新增独立的 CloudBase 集合或数据库字段。
- 不改变当前招聘进度的统计、筛选和终态判断规则。
